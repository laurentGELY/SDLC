Raison d'être

Ce que le modèle résout

Sans gouvernance explicite, Claude Code opère sur des règles implicites — qui disparaissent entre les sessions. Ce modèle rend les contraintes non-négociables, les décisions traçables, et les procédures reproductibles.

01
Vérification exécutable
Tout plan de test contient une commande exacte. Claude itère seul jusqu'à ce que la commande passe — il ne déclare jamais "terminé" sur estimation.
Signal d'alarme : si Claude peut conclure sans preuve observable → violation.
02
Circuit fermé
Toute règle implicite devient explicite (hook, DECISIONS.md, ou Claude.md). Si une contrainte dépend de la mémoire du modèle entre sessions, elle n'existe pas opérationnellement.
Signal d'alarme : observation dans LESSONS_LEARNED sans "Action proposée" → circuit ouvert.
03
Contexte chirurgical
Chaque template liste explicitement les fichiers à charger. Claude ne lit pas le repo en entier — il charge uniquement ce qui est listé dans §Handoff.
Signal d'alarme : template qui demande cat specs/SPEC.md sans condition → lecture non-chirurgicale.
04
Boucle de rétroaction
Toute observation de terrain a un chemin vers une règle permanente. L'ordre : incident → LESSONS_LEARNED → /retrospective → décision → hook ou Claude.md.
Signal d'alarme : règle dans pre-tool-bash.sh sans entrée DECISIONS.md → règle implicite.

Le workflow d'un sprint

Chaque sprint suit le même chemin. L'aval humain est obligatoire avant le code. La vérification est exécutable, pas estimée.

Sprint 0

Bootstrapper un nouveau projet

Le Sprint 0 installe la gouvernance complète avant le premier sprint métier. 9 étapes, un seul commit final. Le script sdlc-init.sh automatise la partie mécanique ; Claude Code complète ce qui demande du jugement.

Initialiser le repo
Créer le dépôt git, commit vide initial.
git init && git commit --allow-empty -m "chore: init repo"
Créer la structure des dossiers
docs/, specs/Sprints/, .claude/skills/wrap-up/, .claude/skills/retrospective/, .claude/hooks/, scripts/
Copier sans modification
specs/sprint-template.md (depuis 04) · .claude/skills/sdlc-sync/SKILL.md (depuis 04b) · .claude/skills/retrospective/SKILL.md (depuis 09)
Adapter Claude.md et STANDARDS.md
Remplir §Rôle, §Démarrage §2, §Limites bash, §Fichier .env, et les seuils de §Barre qualité. Vider §Carte des étapes et §Modules partagés.
grep "\[→ ADAPTER\]\|\[À REMPLIR\]" Claude.md STANDARDS.md → zéro résultat attendu
Adapter wrap-up SKILL
§Étape 0b (chemins git), §Étape 6 (nom projet Claude.ai), déclencheurs §Étape 3 conditionnels.
Créer les fichiers from scratch
CHANGELOG.md · docs/DECISIONS.md · docs/ROADMAP.md · docs/LESSONS_LEARNED.md (avec format Hook + SDLC candidat) · docs/DIAGNOSTIC_CMDS.md · specs/SPEC.md · .claude/skills/diagnostic/SKILL.md
Configurer les hooks
Copier pre-tool-bash.sh, décider des sections [ACTIVER si…] (et du hook PreCompact, optionnel), documenter chaque choix dans DECISIONS.md §D-HOOK-XX, test smoke.
grep "\[ACTIVER" .claude/hooks/pre-tool-bash.sh → zéro résultat
Vérification finale
Critères d'acceptation de 06-PDR-bootstrap.md. Zéro placeholder résiduel. Test smoke hook exit 0.
Commit
Un seul commit final après validation de tous les critères.
git commit -m "chore: bootstrap SDLC vX.Y"
Traçabilité

Le registre des décisions

07-DECISIONS-SDLC.md est la source : chaque décision structurante sur le modèle y porte un identifiant stable M-XXXX-NN, avec son contexte, ce qui a été retenu, ce qui a été écarté et pourquoi. Cette page n'en recopie pas la liste — une copie manuelle dérive. Elle en donne la carte.

M-ARCH-NNArchitecture, structure de fichiersM-ARCH-09 — migration doc/ → docs/, publication du site
M-TMPL-NNContenu et rédaction des templatesM-TMPL-05 — la description d'un skill énonce son déclenchement, jamais la séquence
